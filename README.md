# 一二布布 · 小小大冒险

一二和布布变小了：沙发成了山，零食成了敌人，家里的生活用品成了帮助你突破包围的机关。这是一款基于 Three.js 的单人第三人称动作肉鸽网页游戏，支持电脑和手机浏览器横屏游玩，使用静态文件部署，无需服务器或账号。

本项目是**非商业同人二创**，角色原作者为**黄小B**。本地制作目录的人物参考与 AI 生成重建设定图保存在 `assets/characters/`（历史大图不随网页成品发布）；它们是二创制作参考，并非官方三视图或官方原始图层。立体角色与场景由程序构建；地板、织物、书封和包装由内置 GPT Image 工具生成图集，再以 Canvas 按格裁切，程序纹理作为加载兜底；音效由 Web Audio 合成。

## 开始游玩

选择一二或布布开始一局，角色在本局内固定。攻击会自动进行：通过移动调整与敌人的距离，用镜头方向辅助选择目标，捡取经验并在暂停的三选一界面中选择武器或能力。每人最多装备三把武器，武器最高五级，达到五级时进化。击败每个区域的首领后获得成长奖励，进入下一场景。

| 场景 | 首领出现时间 | 可以利用的物品 |
| --- | --- | --- |
| 客厅 · 晨光地毯 | 2 分 30 秒 | 风扇吹散追兵、多米诺连锁、零食罐挑战 |
| 厨房 · 零食王国 | 2 分 45 秒 | 蜂蜜减速、水壶冲击、零食罐挑战 |
| 庭院 · 午后花园 | 3 分钟 | 旋转喷水器、恢复蘑菇、零食罐挑战 |

表中的时间是各关开始后的生存计时；首领战时间另计，成长选择和暂停期间不计时。击败第三关首领即通关；生命归零则本局结束，可重新选择角色再试。

一二擅长机动，使用「蹦蹦突进」快速穿过危险区域；布布生命较高，使用「抱枕反击」短暂守护后推开敌人。初始武器分别为珍珠奶茶和平底锅，两名角色都可以获得全部武器。

## 操作

| 功能 | 电脑 | 手机 |
| --- | --- | --- |
| 移动 | WASD 或方向键 | 左侧虚拟摇杆 |
| 转动镜头 | 拖动画面，或 Q / E | 右半屏拖动 |
| 角色技能 | 空格 | 技能按钮 |
| 使用附近机关 | F | 交互按钮，接近机关时查看提示 |
| 暂停与继续 | Esc 或暂停按钮 | 暂停按钮 |

准备室的「怎么玩」可查看操作。成长选择时游戏暂停，不必抢着阅读。游戏采用横屏布局；竖屏开始时显示旋转提示并暂停，转为横屏后自动继续。切到后台时自动暂停。设备发热或画面不流畅时，在准备室切换为「流畅」画质；声音可在准备室关闭。

## 当前内容

这是具有完整开局、成长、三关战斗、首领、胜负结算和重开流程的小体量版本，内容规模不等同于借鉴的商业游戏。

- 两名可选角色及不同技能；近景背后跟随镜头，自动攻击与前方辅助选敌。
- 三种主题场景，各包含三种交互物；生活用品不仅作为装饰，也会改变战斗。
- 八把武器：平底锅、珍珠奶茶、回旋拖鞋、泡泡机、闹钟炸弹、拍立得、牵牵围巾、玩具列车，各有五级成长和进化表现。
- 十四种成长能力，覆盖伤害、攻速、范围、生存、连锁、拾取及技能冷却等方向；能力可以重复选择，但有层数限制。
- 追赶、冲锋、远程、重甲、分裂等敌人行为，以及各区域首领战。
- 本机最高击败数记录、声音开关及画质选项。

当前没有在线多人、账号、跨设备存档、在线排行榜或付费系统。最高记录使用浏览器本地存储；清理站点数据会删除记录。

## 本地开发

需要 Node.js 20.19+ 或 22.12+，建议使用当前 LTS。首次运行：

```sh
npm install
npm run dev
```

打开终端打印的 Local 地址。开发服务监听局域网：手机与电脑连接同一网络时，可以在手机浏览器打开终端打印的 Network 地址进行实际触屏测试。请通过 HTTP 服务启动，直接双击 `index.html` 无法正确加载模块。

```sh
# 游戏规则单元测试
npm test

# 生成静态成品到 dist/
npm run build

# 本地预览生产构建
npm run preview
```

画面需要支持 WebGL 2 的现代浏览器。开发预览不代替实际设备上的兼容性与性能验证；低端设备可使用流畅画质。

## 部署到 GitHub Pages

项目提供 `.github/workflows/deploy.yml`，推送到仓库的 `main` 分支后通过 GitHub Actions 构建并部署 `dist/`。Vite 使用相对资源路径 `base: './'`，适配 `用户名.github.io/仓库名/` 这样的项目站点。

1. 将项目文件上传至你的 GitHub 仓库，包含 `package-lock.json` 和 `.github/workflows/deploy.yml`；不要上传 `node_modules/`。
2. 在仓库的 **Settings → Pages → Build and deployment → Source** 中选择 **GitHub Actions**。
3. 推送到 `main`，或从 Actions 页面手动运行部署工作流。
4. 等工作流完成后，使用部署任务返回的 Pages 地址打开游戏。首次启用可能需要等待 GitHub 完成站点发布。

本地文件和工作流配置准备好不代表已经上线；实际公网地址以 GitHub Pages 的成功部署结果为准。也可以把 `npm run build` 生成的 `dist/` 上传至其他静态托管服务。

## 项目结构

| 路径 | 用途 |
| --- | --- |
| `src/main.js` | 游戏循环、战斗、机关、首领、流程和镜头 |
| `src/models.js` | 一二布布、敌人、武器立体模型 |
| `src/world.js` | 三场景、程序纹理、装饰与机关动画 |
| `src/data.js` | 武器、能力、敌人参数及规则函数 |
| `src/input.js` | 键鼠、触屏摇杆和镜头输入 |
| `src/ui.js` | 准备室、战斗界面、成长选择和结算 |
| `src/effects.js` / `src/audio.js` | 战斗视觉反馈与音效 |
| `public/` | 随成品发布的静态资源 |
| `assets/characters/` | 人物二创参考、生成素材及来源说明 |
| `tests/` | 游戏规则测试 |

角色比例与轮廓以用户选定的一二版本为参考；布布全身、双脚与尾巴使用相同棕色，腿脚与身体连续连接。制作参考与图像生成提示词在 `assets/characters/README.md` 及相关 JSON 文件中保留。
